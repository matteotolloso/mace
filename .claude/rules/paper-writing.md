# Paper writing (Overleaf-synchronized manuscript)

## Where the paper lives

- `ICLR27-UQ-MF/` is an **independent Git repository**
  (`origin` = `<paper-repository-url>`) that Overleaf
  syncs through GitHub. The parent repository ignores it (`/ICLR27-UQ-MF/` in
  `.gitignore`); commit and push paper changes from inside that folder.
- Main file: `iclr2027_conference.tex` (ICLR 2027 template). It inputs
  `math_commands.tex`, uses `iclr2027_conference.{sty,bst,bib}`, `fancyhdr.sty`,
  `natbib.sty`, and loads figures from `figures/`.
- Keep this layout. Overleaf compiles from the repository root: do not move,
  rename or nest the main `.tex`, the style files or `figures/`.
- Anything committed there appears in Overleaf. Commit only files the paper
  needs. Keep build products, notes and Claude files out of it: they are listed
  in the paper repo's local `.git/info/exclude`, which is never pushed.
- The previous NeurIPS version is kept for reference as
  `notes/_Nips26__UQ_MF-3.pdf` in the parent repository.

## Content rules

- Do not rewrite paper text, claims, citations or results unless asked.
- Every number in the paper must trace to a `results/results.md` entry or to a
  generated artifact that such an entry points to (see `reproducibility.md`). If a
  number cannot be traced, flag it instead of repeating it.
- Figures come from code in the parent repository. Current rebuilt main-text
  figures are generated by `new_figures/` into `new_figures/out/*.pdf`; copy a
  PDF into `ICLR27-UQ-MF/figures/` only when it is meant to replace a paper
  figure, and record which script and commit produced it.
- The appendix is due to be rewritten. Its figure references under
  `figures/experiment_*/` point to files that are not in the repository; this is
  known and expected, so do not add or regenerate those figures unless asked.
- Before using any figure or CSV from `experiment_X/evaluation/`, read
  `../experiments/evaluation_figures.md` (path from the paper folder; the file is
  `experiments/evaluation_figures.md` in the parent repository). It says what each
  figure shows and whether it may back a claim. In short: prefer the
  `-log-scale` epoch-quality variants; do not use `finetune.svg`,
  `energy_ood.svg`, `distribution_*.svg`, or any energy-split (C, D, F) OOD
  epoch-quality curve, because they are unfiltered or misleading; the per-split
  `cache/` figures are single replicates.
- Draft sections written outside the paper repo (e.g. `new_figures/results.tex`)
  are not part of the manuscript until the user asks to merge them.
- The active-learning study is a proof of concept and is not part of the current
  manuscript's sections or figures; keep AL claims separate unless the user
  explicitly extends the paper.

## Manuscript consistency checks

Do not silently change code or old results to match the paper. Raise these when
editing methods, equations, captions or reproducibility claims:

1. The code computes EU with the population variance (`unbiased=False`,
   denominator `M`); the manuscript's EU equation uses `1/(M-1)`.
2. The manuscript describes a fixed random seed; the repository uses five
   dataset split seeds (`0..4`) and ten member seeds (`0..9`). B/D/wB fine-tuning
   configs use 100 epochs, pretraining/direct runs 300.
3. In the system-shift dynamics figure (Fig. 4), the ID and OOD columns plot AUSE
   in the row labelled "Spearman", ENCE in the row labelled "AUSE", and Spearman
   in the row labelled "ENCE". This was verified against the split-0 caches
   (r = 1.000) in the NeurIPS draft (`notes/_Nips26__UQ_MF-3.pdf`, p. 7); the
   ICLR27 file `figures/dynamic-sytem-shift.pdf` has not been re-checked, but its
   text cites the same panels. The train column is correct.
4. The repository now reports five-split intervals with the geometry-only
   support filter and no `--trim`; figures and tables made before that change
   use split 0 and the total-variance trim. Check which version a figure came
   from before updating a claim.
5. Water results now cover five splits (older water figures are split 0 only), and
   the water BLYP/CCSDT splits are not aligned (see "Audit notes and known issues" in `README.md`).
